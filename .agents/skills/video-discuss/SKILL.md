# 讨论与设计

明确视频项目，阅读本次相关的文稿、设计、素材或结果；已有结论直接沿用。项目结构与结果定位见 [项目约定](../video-produce/references/project-layout.md)。
访谈复用通用 `/grilling`，只澄清当前缺口；主动说明推荐、异议、依据和未知，尊重使用者理解取舍后的创作偏好。

## 初始创作

共同决定文字、画面与音乐如何分担表达。音乐、结构与视觉可以相互影响；提供的曲目作为候选，讨论采用曲目与选段。
设计足以包含目标受众与核心内容、宏观结构与大致节奏、视听分工与当前方向、重要限制及未决／试验范围即可。
需要新的创作思路时按题材参考上游 [story](../../../vendor/hyperframes/skills/hyperframes/references/story.md)、[sound](../../../vendor/hyperframes/skills/hyperframes/references/sound.md)。

## 反馈

1. 对应使用者实际看的结果与位置；可接受“第二屏太快”等自然语言，存在歧义才澄清。旧版本的位置须重新对应当前内容。
2. 把模糊反馈解释为可检验的假设，推荐最小但足够的尝试，保留未受影响的已认可内容。已明确且获授权的局部修改可直接交给 `/video-produce`。
3. 可在授权范围内试验；影响内容含义、关键解释、已确认结构或总时长时重新讨论。

必须实际看听才能决定的问题，交给 `/video-prototype`；作品的持续迭代使用视频草稿，尽早呈现整体结构与节奏。

## 总结与设计

1. 总结本轮已采纳、仍在试验和未解决的内容及必要理由，按 [设计与执行](../video-produce/references/project-layout.md#设计与执行) 说明拟更新的设计文件；使用者确认保存后落盘。
2. 明确请求整理已有共识时直接整理；未知仍标为未知。小反馈只同步实际受影响的设计，精确实现参数留在源码。
3. 引用文稿、素材、原型与制作依据，保持设计与后续规格同一份正文。
4. 返回文件路径、关键变化和未决内容，到此停止。制作、拆票和委派分别遵循本次实际授权。

人工换会话时遵循 [跨会话接续](../video-produce/references/project-layout.md#跨会话接续)。
