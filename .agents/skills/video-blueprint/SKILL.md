# 整理创作设计

1. 确定项目及目标文件，读取已有设计和探索总结。已有正文就在原处更新；没有时默认使用项目根的 `design.md`。
2. 整理已形成的共识、重要理由、限制、试验范围与未决问题。缺失的依据保留为未知，不替人作新选择或重新启动全量访谈。
3. 保持宏观设计足以指导下一步即可，按实际需要补足；不套长用户故事、测试章节或完整逐镜规格。
4. 引用已有文稿、素材、原型和制作依据；精确实现参数留在源码，设计引用它们，避免重复维护。
5. 返回文件路径、关键变化和仍待决定的内容，到此停止；落盘不自动触发制作、拆票或委派。

蓝图与后续规格保持同一份正文，不为“进入下一阶段”另抄一份。
