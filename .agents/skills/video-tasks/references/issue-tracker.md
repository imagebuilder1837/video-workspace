# 视频项目 tracker：本地 Markdown

仅用于采用此约定的视频项目。已有项目约定优先沿用，保留其位置与状态文字，按下述执行语义映射；无法对应时先澄清。

## 文件与操作

- 每项工作使用 `.scratch/<事项>/issues/<NN>-<短名>.md`，一票一文件，编号从 `01` 起，新增票接续已有编号，依赖优先编号；跨事项依赖用可解析的票路径。
- “发布”即创建票文件，“读取”即按路径或编号找到相应票并读正文与讨论。有实际工作时创建票。
- 票包含标题、交付目标、必要范围与设计／资料指针、`Blocked by:`、`Status:` 和验收条件。无依赖写 `None`；必要讨论与处理说明追加到 `## Comments`。
- 票引用当前设计及相关材料，共享正文的写入责任见 [设计与执行](../../video-produce/references/project-layout.md#设计与执行)。

## 状态

| `Status:` | 含义 |
| --- | --- |
| `ready-for-agent` | 工作单已明确、尚未派发；仍须满足依赖才可开始。 |
| `in-progress` | 已派发执行，包括正在修正的任务。 |
| `integrated` | 交付已集成，可供适用下游使用，尚未完成本轮统一核查。 |
| `done` | 本轮执行、一次独立审查及必要修复已完成。 |
| `cancelled` | 工作已取消，票内说明原因及适用的替代任务，并重整下游依赖。 |

## 推进

- 主代理在派发、集成、阻塞变化与完成等有意义节点统一维护；执行子代理回报。
- 可开始的任务是尚未派发且依赖交付已具备的票。依赖通常在 `integrated` 或 `done` 时可用；若交付本身是人的判断或检查结论，须实际取得。运行中临时阻塞在票内说明原因和所需条件。
- Review 后需要修复的任务回到 `in-progress`，修复集成后按本轮结果结案；关键人工取舍尚未得到时保留阻塞说明。检查轮次由 [`/video-coordinate`](../../video-coordinate/SKILL.md#统一审查与修正) 规定。
- 设计变化只更新受影响票与依赖，保留未受影响内容；取消上游时须重整下游。小反馈沿用相关任务，确需独立跨上下文跟踪时才增票。
