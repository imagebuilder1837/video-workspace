# 整理视频任务

复用通用 to-tickets 的拆分、确认和一票一文件机制，按视频交付目标组织，不套软件分层或测试模板。

1. **读取依据**：明确项目与本次工作范围，读取本地指引、当前设计、已有相关票及讨论。已有设计直接引用，确需补足时仍维护同一份正文；创作取舍不清转 [video-discuss](../video-discuss/SKILL.md)，不在拆票时代作决定。
2. **提出拆分**：每票对应可交付、可判断、适合一个新上下文承担的目标，只列真正阻塞的依赖。按需要拆音频分析、原型、局部制作或检查，不固定按工种、场景或操作步骤建票；已有充分依据的局部工作可以直接成票。
3. **确认粒度**：向使用者展示每票标题、交付目标、依赖与验收条件，询问是否需要合并、拆分或调整依赖；确认后才发布。
4. **发布工作单**：按项目实际 tracker 写入；本地 Markdown 读取并遵循 [任务约定](references/issue-tracker.md)。特殊禁区、素材或时间约束按需补充。
5. **返回并停止**：给出任务路径、依赖及当前可开始的任务，不自动执行或委派。后续协调需使用者明确调用 video-coordinate，并满足其项目 Git 与 tracker 前提。

没有 tracker 时可在对话中提出拆分；需要发布则提示先运行 video-setup，不擅自配置或改用工作台 GitHub Issues。不自动修改或关闭来源规格。
