# 项目结构与结果

## 结构

遵循上游默认入口与目录惯例；新项目从 `projects/example/` 复制必要结构及忽略规则，保留已有项目的组织和用户修改。

| 位置 | 用途 |
| --- | --- |
| 根 `index.html` | 默认制作入口；实际制作时创建，不为统一目录而搬进 src。 |
| 根目录 | 原始文稿、参考说明及确认后形成的 `design.md`；已有设计在原处维护，不另抄正文。 |
| `assets/` | 项目素材和显式共享链接，按需细分；引用规则见 [本地文件](local-files.md)。 |
| `compositions/` | 按需拆分的场景与组件源码，简单作品可不拆。 |
| `renders/` | 视频草稿、连续片段、导出与需要保留的画面证据。 |
| `prototypes/<问题短名>/` | 回答具体问题的独立原型目录，见 [video-prototype](../../video-prototype/SKILL.md)。 |
| `.hyperframes/` | 工具自行生成的状态、历史与部分缓存，不预建或整目录删除。 |

模板只用 .gitkeep 保留四个目录，不预填作品、空设计或任务。不强制 init、项目 package.json 或元数据；配置只在改变实际行为时增加。
项目 Git 排除视频、大媒体、生成物与缓存，保留轻量源码、设计和目录链接；不用 Git 时不另造源码快照系统。

## 设计与执行

- 设计按内容组织当前目标、约束及试验范围，不代表源码或已有产物已符合它；执行进度归 tracker，符合度由实际结果的 review 判断。
- 共享设计由发起本次制作的会话维护，执行子代理遵守可改范围、回报完成内容及所需设计调整；若委派修改共享设计，明确独占写入范围。
- 简单项目未启用 tracker 时，制作返回实际完成、未完成与检查边界；需要持久拆分或跨会话跟踪时，可人工调用 video-setup 配置，再用 video-tasks 建立必要工作单。

## 结果对应

- 已有上下文能唯一确定结果就沿用，存在歧义才澄清，不默认选择最新文件。保留正在讨论、比较和交付的结果，不覆盖仍在使用的版本；临时排错输出按需清理。
- 导出结果明确实际文件、帧率及全片／片段跨度。默认用对应版本的全片时间，片段虽从零播放仍可映射到全片；场景局部时间与音乐源时间须标明。
- 预览明确项目、实际 URL 和检查时的源码状态；相同 URL 不代表同一版本，源码变化后不能沿用旧检查。需要固定可回看的动态证据时按需导出片段。
- 使用项目 Git 且需保留制作版本时，注明实际源码提交与未提交变化；不以提交号冒充其未包含的修改，不逐次渲染登记。跨会话沿用已有资料或人工触发的临时 handoff 引用结果，不新增编号制度或登记文件。
