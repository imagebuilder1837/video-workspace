# 项目结构与结果

## 结构

遵循上游默认入口与目录惯例；新项目从 `projects/example/` 复制必要结构及忽略规则，保留已有项目的组织和用户修改。

| 位置 | 用途 |
| --- | --- |
| 根 `index.html` | 默认制作入口，实际制作时创建。 |
| 根目录 | 原始文稿、参考说明和创作设计。 |
| `assets/` | 项目素材和显式共享链接，按需细分；引用规则见 [本地文件](local-files.md)。 |
| `compositions/` | 按需拆分的场景与组件源码。 |
| `renders/` | 视频草稿、连续片段、导出与需要保留的画面证据。 |
| `prototypes/<问题短名>/` | 回答具体问题的独立原型目录，见 `/video-prototype`。 |
| `.hyperframes/` | 工具自行生成的状态、历史与部分缓存。 |

最小制作起点为根 `index.html` 及实际引用的素材和动画；配置只在改变实际行为时增加。
项目 Git 排除视频、大媒体、生成物与缓存，保留轻量源码、设计、配置、必要任务资料和目录链接。

## 设计与执行

- 设计正文在已有位置维护，新设计默认项目根的 `design.md`；内容组织当前目标、约束及试验范围。执行进度归 tracker，符合度由实际结果的 review 判断。
- 共享设计由发起本次制作的会话维护，执行子代理遵守可改范围、回报完成内容及所需设计调整；若委派修改共享设计，明确独占写入范围。
- 简单项目未启用 tracker 时，制作返回实际完成、未完成与检查边界；需要持久拆分或跨会话跟踪时，可人工调用 `/video-setup` 配置，再用 `/video-tasks` 建立必要工作单。

## 结果对应

- 已有上下文能唯一确定结果就沿用，存在歧义才澄清。保留正在讨论、比较和交付的结果；临时排错输出按需清理。
- 导出结果明确实际文件、帧率及全片／片段跨度。默认用对应版本的全片时间，片段虽从零播放仍可映射到全片；场景局部时间与音乐源时间须标明。
- 预览明确项目、实际 URL 和检查时的源码状态。需要固定可回看的动态证据时按需导出片段。
- 使用项目 Git 且需保留制作版本时，注明实际源码提交与未提交变化。

## 跨会话接续

人工跨会话接续由使用者明确调用原版 `/handoff`；交接记录保存在操作系统临时目录，引用已有设计、任务和结果，由使用者传递路径。
