# 视频原型

1. 明确待验证问题、实际视频项目、相关设计与素材、保持不变的约束、允许试验的范围及所需判断。只澄清缺口，不重新做全局创作访谈；换会话时由人使用原版 handoff 传递这些指针，不强制换会话。
2. 按 [项目约定](../video-produce/references/project-layout.md) 使用 `prototypes/<问题短名>/`，先核对现有内容。每个问题一个目录，不按每次修改建立版本目录树；只放必要文件，复用素材，不复制整个项目作为快照。
3. 有项目自己的 Git 时使用临时分支隔离，不误用工作台 Git；先核对当前分支与未提交工作，无法安全隔离时说明并确认，不能擅自覆盖或 stash 用户改动。无项目 Git 时直接用原型目录，不自动初始化 Git，也不承诺历史恢复。
4. 用 [video-produce](../video-produce/SKILL.md) 制作最小可判断呈现，将原型目录作为显式项目目录，使用其根 `index.html`，按需建立 assets、compositions、renders。必要共享链接按新位置计算，不误改或覆盖正式作品。按问题选择方案数量，不默认制作多套或顺便完成整片。
5. 有足以判断的证据后，使用项目 Git 的将需保留的原型源码提交到临时分支，只纳入本次原型文件，保留分支，不自动推送；视频仍在 Git 外。无 Git 时保留必要原型文件。
6. 返回原型目录、适用的分支／提交、预览／产物、实际尝试、证据局限及待判断问题。取自全片时说明对应范围，独立试验没有映射则明说；布局可用静帧，节奏和音乐须给连续音画，没有真实感知能力就由人观看／试听，不代答偏好。由使用者把判断带回主线的 [video-discuss](../video-discuss/SKILL.md)，确认结论并更新主设计；同会话可直接接续。有项目 Git 时，接续正式制作前核对工作区并安全切回原制作分支，保留原型分支和交付证据。主线不自动合入整份原型，后续制作按已确认方向另行推进。
