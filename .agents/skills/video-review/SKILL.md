# 视频结果 review

## 执行

1. 明确具体结果、项目上下文、关注范围及适用设计和必要制作依据，按 [结果对应](../video-produce/references/project-layout.md#结果对应) 消除歧义。只有媒体文件时也可检查能确认的部分，说明依据不足而不能判断的内容，不要求先建项目或补完整设计。
2. 分别检查下述两轴。结合实际产物、制作阶段、当前问题与风险自行选择检查方法和代表性样本，异常时扩大范围；取证见 [工具与证据](references/evidence.md)。代码 diff、渲染成功或空检查结果均不能替代产物检查。
3. 只生成必要证据，不修改源码、设计或覆盖被审结果。可由主 agent 执行，或在获授权后委派检查；不强制固定分工或每个制作执行者自检。明确要求修复时，由主 agent 按授权接续 [讨论](../video-discuss/SKILL.md) 或 [制作](../video-produce/SKILL.md)。

## 检查轴

| 轴 | 方向与依据 |
| --- | --- |
| 技术可靠性 | 检查文件与播放、素材加载、画面及动态呈现、音频的基础可靠性，依据实际技术证据和适用输出要求判断。 |
| 设计符合度 | 对照已采纳设计，检查内容与结构、视觉与节奏、音乐及音画安排；缺少依据时说明无法判断，不补造标准。 |

两轴分别报告，不相互抵消。工具警告是线索，不自动等于缺陷；通用审美偏好不是项目要求。有依据的体验建议可提出，但须标明是判断或风险，而非技术故障或设计违例。

## 返回

默认在对话或子代理返回中给出以下清单，无须填满无关项；明确要求留存时才保存报告，不固定生成 `REVIEW.md`。

1. **对象与依据**：具体结果、版本、时间范围、本次问题与设计依据。
2. **检查清单**：分别列出两轴实际检查的方法、覆盖和结果；适用却失败、跳过或无法判断的项明确说明。
3. **问题与建议**：每项说明位置、观察、依据或影响及最小调整建议；没有问题时简短说明，不凑建议或给全片总分。
4. **未覆盖与人工补位**：区分技术证据、静帧观察、连续动态与实际听感；没有真实视频或音频感知能力就明说，并给出需要人观看／试听的具体问题。

最终仍针对实际交付文件完成适用检查，由使用者完整观看、试听；预览和旧版本的结论不能替代交付文件的检查。

## 修改后复查

局部修改检查该处及前后衔接；改变后续时间安排时覆盖受影响后段；更换音乐、全局字体、尺寸或帧率等变化时相应扩大到全片。
保留仍适用的未受影响判断，复查须取得修改后结果的证据，不能把旧结果或未覆盖内容当成当前已检查。
