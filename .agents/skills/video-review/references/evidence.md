# 工具与证据

按实际对象与当前问题选工具。

| 对象 | 现成工具与边界 |
| --- | --- |
| 项目源码加载后的浏览器结果 | 从工作台根用 `npm run hf -- check <项目> --json`、`snapshot`；参数读上游 [lint/check/snapshot](../../../../vendor/hyperframes/skills/hyperframes-cli/references/lint-validate-inspect.md) 与已安装 CLI 的 `--help`。 |
| 实际导出文件 | 用 ffprobe 核对容器和流的尺寸、帧率、时长等信息，用 FFmpeg 解码、抽取实际编码帧及所需区间。 |
| 实际音轨 | 可用 `npm run hf -- audio <文件> --quality fast` 或 FFmpeg 测量响度、静音等；项目 `check` 的音频检查针对源素材，外联边界见 [音乐指引](../../video-produce/references/music.md)。 |
| 连续音画 | 源码预览与区间导出沿用 [制作](../../video-produce/SKILL.md)；检查已有文件时播放或从该文件取片段。流复制切点受关键帧与时间戳限制。 |

## 解释工具结果

- 查看实际 findings、浏览器是否跳过、各审计是否启用及真实样本时间／数量、截断与失败。
- `check --range` 下部分审计会跳过；`--components` 仅筛选显示，须查看隐藏 findings。依据真实覆盖报告。
- 核对缓存证据是否仍对应当前源码与输入，必要时重新检查。需要讨论的证据留在正式项目的 `renders/`；`.hyperframes/` 含工具历史。
- 沿用工作台入口，工具警告结合实际画面与设计判断。

## 证据是否足够

画面清晰度须足以判断当前问题，细字与布局按目标输出清晰度观察；节奏与音画问题需要正常速度、连贯且带相应音频的证据。
预览卡顿时定位原因或用导出片段核验，预览与编码结果有差异时在对应位置比较。缺陷妨碍当前判断时先提供有效证据或说明受阻原因；其余已知问题可说明后继续。

## 感知与人工补位

如实说明实际使用的连续视频与音频感知能力，将技术测量、静帧观察、连续动态和听感分别报告。感知能力或证据覆盖不足时，列出需由使用者观看／试听的具体问题。最终由使用者完整观看、试听实际交付文件。
