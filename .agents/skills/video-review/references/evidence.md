# 工具与证据

按实际对象与当前问题选工具，不把项目源码的检查当成已有导出文件的检查。

| 对象 | 现成工具与边界 |
| --- | --- |
| 项目源码加载后的浏览器结果 | 从工作台根用 `npm run hf -- check <项目> --json`、`snapshot`；参数读上游 [lint/check/snapshot](../../../../vendor/hyperframes/skills/hyperframes-cli/references/lint-validate-inspect.md) 与已安装 CLI 的 `--help`。不是任意 MP4 的审计器。 |
| 实际导出文件 | 用 ffprobe 核对容器和流的尺寸、帧率、时长等信息，用 FFmpeg 解码、抽取实际编码帧及所需区间；元数据可读不等于全片可解码，成功解码也不证明播放器兼容、连续动态或听感合格。 |
| 实际音轨 | 可用 `npm run hf -- audio <文件> --quality fast` 或 FFmpeg 测量响度、静音等；项目 `check` 的音频检查针对源素材，不是导出混音。分析与测量均不等于试听，外联边界见 [音乐指引](../../video-produce/references/music.md)。 |
| 连续音画 | 源码预览与区间导出沿用 [制作](../../video-produce/SKILL.md)；检查已有文件时播放或从该文件取片段，不能重渲染新源码冒充旧文件。流复制切点受关键帧与时间戳限制，不能当作精确裁剪。 |

## 解释工具结果

- 查看实际 findings、浏览器是否跳过、各审计是否启用及真实样本时间／数量、截断与失败；零样本或空章节不算通过，退出码和顶层 ok 不能替代这些判断。
- `check --range` 不会把全部子检查局部化，部分审计会跳过；`--components` 仅筛选显示，须查看隐藏 findings。依据真实覆盖报告，不从所选参数推断覆盖。
- 核对缓存证据是否仍对应当前源码与输入，必要时重新检查。保留需要讨论的证据到不受自动清理的位置；`.hyperframes/` 含工具历史，不应整目录清空。
- 沿用工作台入口，不照搬上游固定 gate、自动修复、评分或反馈上传流程；工具警告结合实际画面与设计判断。

## 证据是否足够

画面清晰度须足以判断当前问题，细字与布局按目标输出清晰度观察；节奏与音画问题需要正常速度、连贯且带相应音频的证据。
预览卡顿时定位原因或用导出片段核验，预览与编码结果不一致时在对应位置比较，不能以一方为另一方背书。缺陷妨碍当前判断时先提供有效证据或说明受阻原因；不妨碍的已知问题可说明后继续。
