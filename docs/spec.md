# 工作台行为规范

## 视频项目与执行范围

- 视频项目采用上游组织，独立 Git／tracker 仅按明确请求建立。
- 会话从工作台根进入；HyperFrames CLI 与上游辅助脚本在明确的目标项目／试验范围执行，每次使用工作台绝对路径的 `bin/workspace-env <原命令及参数>`。
- 制作复用已安装工具，技能及 CLI 的安装、更新由使用者管理。缺失或不兼容时报告实际影响；上游 `npx` 固定版本调用先核对安装与版本切换行为。
- 源码与素材正常保留，备份、归档及删除由使用者决定；上游 history 不等于完整备份。

```sh
W=/absolute/path/to/video-workspace
cd "$W/projects/<项目名>"
"$W/bin/workspace-env" hyperframes check
"$W/bin/workspace-env" node /absolute/path/to/installed/skill/script.mjs <参数>
```

多条命令可分别包装，或通过入口执行同一个 shell。`npm --prefix` 运行工作台包脚本会切回包根，项目操作使用上述入口。技能、依赖、配置或浏览器异常时，参阅 [环境排错](development.md#升级与排错)。

## 素材与本地数据

- 工作台 `.media/` 上游媒体库承担跨项目复用，包含长期素材、登记与偏好数据。清理可重建缓存时保留该库。
- 手动素材通过上游导入与登记进入管理；仅复制文件进库目录不会建立完整索引。项目素材的原地登记／接管，与提升到跨项目库须分别核对结果。
- 项目素材与必要冻结副本沿用上游方式。现有 `shared/` 与归档作品的接管、搬迁或修复由使用者另外决定。
- 视频项目、素材、渲染结果、缓存和本地凭据留在工作台 Git 之外；依赖锁与实际生成的项目技能来源锁保留。技能正文及代理链接按实际安装位置忽略。

## 验证与证据

技能可用性按实际安装位置验证发现、相对参考与辅助脚本依赖；明确使用其他上下文时另验其可用性。CLI 包附带技能文件不等于 agent 已发现技能。

区分信号测量、辅助模型分析、静帧、连续动态与人工听感。辅助分析注明模型来源并核对源时间映射，感知结论以实际看听为依据。

验收使用合成素材、隔离 home／素材库和本地替身，避免接触真实账号或上传音乐。分别报告通过、失败、跳过与安装后待验证；媒体引擎、预览素材列表及实际浏览器行为分别验收。
